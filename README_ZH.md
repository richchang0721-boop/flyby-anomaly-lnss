# LNSS / 擾動模型 — 地球飛掠異常研究

**語言切換：[English](README.md) | [繁體中文](README_ZH.md)**

*獨立研究專案：探討地球飛掠異常——太空船以雙曲線軌跡飛掠地球時，觀測到的無法解釋的毫米/秒等級速度異常。*

</div>

---

## 這是什麼

自1990年起，多艘進行地球重力助推飛掠的太空船（Galileo、NEAR、Cassini、Rosetta、MESSENGER、Juno）相對標準軌道力學預測，都出現了微小（毫米/秒等級）且無法解釋的速度異常——即 **Anderson 飛掠異常**（Anderson et al. 2008, PRL）。本專案記錄一個獨立研究嘗試，透過對已知物理的最小擴展（**LNSS / 擾動模型**框架，一個受地球自轉擾動的背景場）來解釋這個異常。

這是**獨立研究**，非同行評審發表。所有結果（包含負面結果與過去的錯誤）都誠實記錄——完整的發現、修正、推翻過程見 [CHANGELOG.md](CHANGELOG.md)。

## 目前狀態（2026-07-03）

**已確立、高信心的結果：**
- **封閉軌道拓樸定理：** 任何封閉軌道的 ΔV 精確為零（已證明，並以ISS/GPS幾何驗算）——框架目前最強的結果。
- **Anderson公式的因子2** 追溯到雙程Doppler追蹤方法論，並給出量化誤差上界（往返兩腿的不對稱修正量級為 O(v²/c²) ~ 10⁻⁹，可忽略）。
- **Anderson P₁ 公式**（ΔV = V∞·(2ωR/c)·(cosδᵢ−cosδₒ)）已用 JPL Horizons 重建的軌跡角度對7個歷史飛掠中的6個驗證，誤差在 ~0.2 mm/s 以內（見[可重現計算流程](#可重現計算流程)）。

**2026-07-02 被推翻的結果（完整細節見 CHANGELOG.md）：**
- 框架早期版本使用的歷史 δ_peri（近地點赤緯）數值，從未留下任何計算方法的記錄，且被發現物理上不自洽（例如 Galileo I 的舊值超出其軌道傾角本身允許的赤緯上限）。用 JPL Horizons 原始向量完整重建後，以下結果被推翻：
  - **候選7**（拓樸節點分類，原稱「7/7準確率」）——在全部7個重建飛掠中，δ_peri 貢獻的正確分類數為0。
  - **|P₂(cosδ_peri)| 與 |ΔV| 的相關性（r=0.852）**，曾是框架「幾何為主導因素」核心論述的依據——用修正後的 δ_peri 無法重現（位置定義：r=+0.082，無相關；速度定義：r=−0.863，方向相反，邊緣顯著）。
  - **Juno 本身的 δᵢ、δₒ**（不只 δ_peri）也被發現有誤；修正值與獨立文獻（Jouannic et al. 2015；Acedo 2017）幾乎完全吻合。Juno「未消去的P₁預測」由原本聲稱的 +10.4 mm/s 修正為 ~6.0–6.3 mm/s。

**待解問題：**
- **RQ4：** 為何 Juno 的觀測 ΔV 為零，即使 Anderson P₁ 預測非零（~6mm/s）——仍未解決。
- **RQ12：** κ = 1/B_main（B_main = 16,076 km）的物理來源——無法從地球局域常數推導（窮舉維度分析已排除），已重新表述為框架的自由參數，初步傾向支持它是背景場的固有性質，而非受局域環境調制（見 07_Open_Problems.md）。
- δ_peri 的正確定義（位置赤緯或速度赤緯）尚無定論。

**即將到來的可證偽測試：**
- **JUICE 飛掠，2026-09-28/29** 與 **Europa Clipper 飛掠，2026-12-03**——密封預測見 `05_Predictions.md`，在觀測結果公布前寫定，事後不得修改。

## 可重現計算流程

本專案一個重要的方法論發現（2026-07-02，完整記錄見 `CHANGELOG.md`）：純粹以文字形式存在、沒有可追溯計算來源的數值，即使被反覆引用數週，仍不可信任。因應此發現，所有軌跡衍生的數字現在都遵循固定流程：

```
data/raw/*.txt  (JPL Horizons，赤道/ICRF座標，地心，1分鐘步長)
      ↓
reconstruct.py   (尋找精確近地點，計算位置與速度赤緯)
      ↓
validation_tests.py   (自動化檢查：高度是否符合官方值、赤緯是否在傾角物理上限內等)
      ↓
results.json   (δᵢ、δₒ、δ_peri、近地點高度等的唯一權威來源)
```

**任何人（人類或AI）review本研究時的規則：** 軌跡衍生的數值主張，應該對照 `results.json`，或用 `data/raw/` 裡的原始資料重跑 `reconstruct.py` 來驗證，不應該憑記憶重新生成、或單純用文字推理重新推導。

重現方式：
```bash
python3 reconstruct.py data/raw/Galileo01_horizons_results_min.txt 960
python3 validation_tests.py results.json
```

## 方法論與AI參與

本研究由作者與兩個AI系統（GPT、Claude）協作完成，AI作為推理與計算執行的輔助工具——而不是未經驗證的事實主張來源。專案進行中期學到的一個關鍵教訓（完整記錄於 `CHANGELOG.md`）：LLM生成的數值結果，即使被反覆引用、看起來前後一致，仍可能共享未被察覺的錯誤——因為不同模型或不同對話之間，單靠文字層面的交叉review，並不保證能互相抓出對方的盲點。

之後採用的工作原則：

> **AI 可以參與推理，但不能成為事實主張的起點。**

具體而言：任何描述物理現實的數字，都應該可以追溯到一個外部、可執行的來源（例如透過 `reconstruct.py` 執行的JPL Horizons查詢），而不是追溯到一段LLM生成的文字。跨模型討論（Claude/GPT）用來產生假說、找出彼此的思考盲點，而不是用「多個模型都同意」來當作真實性的驗證。
